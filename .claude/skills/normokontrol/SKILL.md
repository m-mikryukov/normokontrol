# Нормоконтроль документа

Главное правило: меняем только оформление. Формулировки, выводы, цифры и цитаты автора не трогаем. Ошибки содержания (ссылка на несуществующий рисунок, нет источника) — в отчёт, а не молча в текст.

## Где лежат инструменты

`NK` — каталог, где рядом лежат `scripts/`, `profiles/` и `references/`:
- в репозитории — его корень (скилл лежит в `.claude/skills/normokontrol/`, значит `NK=../../..` от него);
- в собранном скилле (`scripts/build_skill.sh`) — сам каталог скилла.

Зависимости: `pip install python-docx PyYAML`. Для рендера нужен LibreOffice (`soffice`) и `pdftoppm`.

Рабочие файлы складывай в отдельный каталог (например, `out/`), исходный файл не перезаписывай.

## Порядок работы

1. **Тип документа — первым вопросом.** От него зависит стандарт: разные ГОСТы регулируют разные документы. Покажи пользователю меню:
   ```
   python3 $NK/scripts/catalog.py
   ```
   и спроси, что нужно оформить: отчёт о НИР, ВКР, курсовую, реферат, отчёт о практике, диссертацию, автореферат. Не угадывай по файлу — спроси, даже если тип кажется очевидным. Можно подсказать: «похоже на курсовую — верно?».
   - Тип с пометкой «не поддерживается» (например, техническая документация по ЕСКД) — честно скажи, что этот вид пока не оформляешь и почему, и предложи только проверку общих вещей по ближайшему профилю с оговоркой.
   - Тип «частично» (автореферат) — до начала работы скажи, что именно будет проверено, а что нет.

2. **Требования организации.** Для учебных работ спроси методичку вуза, для диссертации и автореферата — требования диссертационного совета. Они главнее ГОСТа. Если в `profiles/` уже есть профиль вуза или совета (`catalog.py` их показывает) — используй его. Если пользователь прислал методичку — составь профиль-наследник от профиля из каталога (`extends: …`, только отличия, см. `profiles/README.md`), значения бери из методички, а не по памяти. Нет методички — работай по базовому профилю и напиши об этом в отчёте. Чего нет ни в методичке, ни в профиле — не выдумывай, спроси или отметь в отчёте.

   Перед проверкой назови пользователю, по каким стандартам будешь проверять и их статус (`catalog.py --standards`). Если дата проверки статуса старше года, утилита помечает «перепроверить» — тогда проверь статус в реестре Росстандарта, прежде чем опираться на стандарт.

3. **Проверка до правок.**
   ```
   python3 $NK/scripts/audit.py work.docx --profile <id> --json out/before.json --out out/before.md
   ```
   Покажи пользователю сводку: сколько нарушений, главные группы. Каждое помечено, кто исправляет: `авто` — скрипт, `Claude` — ты, `автор` — только автор.

4. **Механика скриптом.**
   ```
   python3 $NK/scripts/fix_layout.py work.docx -o out/work_nk.docx --profile <id>
   ```
   Исправляет поля, формат, шрифт, кегль, цвет, интервал, отступы, выравнивание, заголовки (прописные, полужирный, по центру, с новой страницы, без точки), подписи («Рис. 1.» → «Рисунок 1 —»), номера страниц. Всё — в режиме рецензирования. Строки «Не удалось исправить автоматически» из вывода переходят в шаг 5.

5. **Смысловое оформление — сам.** Повторно запусти `audit.py` на `out/work_nk.docx` и разбери пункты с пометкой `Claude`:
   - заголовок без стиля «Заголовок» — назначь стиль Heading нужного уровня;
   - подпись не на своём месте (у таблицы — над, у рисунка — под) — перенеси абзац;
   - заголовок списка источников — приведи к профилю;
   - список источников — сверь каждую запись с `references/bibliography.md`; правила ссылок — `references/gost-r-7.0.5-2008.md`, исправь знаки и порядок элементов; недостающие сведения (год, страницы, дата обращения) не выдумывай — в отчёт;
   - порядок источников, если профиль требует `by_citation`, — предложи автору, сам не переставляй без согласия: это меняет номера ссылок в тексте;
   - содержание, набранное вручную, — посоветуй собрать автоматически.

   Правь XML через python-docx/lxml и вноси изменения как рецензирование: для текста `w:del`/`w:ins`, для свойств `w:pPrChange`/`w:rPrChange`. Готовые помощники — класс `Revisions` в `scripts/nk_tracked.py` (`replace_span`, `para`, `run`). Если доступен скилл `docx`, можно опираться и на него.

6. **Рендер и проверка глазами.**
   ```
   ACCEPT=1 $NK/scripts/render_check.sh out/work_nk.docx out
   ```
   Посмотри PNG страниц: титульный лист без номера, номер страницы там, где требует профиль (у диссертации — вверху), структурные элементы и главы с новой страницы, рисунки по центру, подписи на местах, ничего не съехало. То, что скрипты не проверяют (например, три интервала вокруг заголовков диссертации), проверь здесь. Нашёл проблему — исправь и отрендери снова.

7. **Сдача.** Отдай `out/work_nk.docx` (правки видны в Word: Рецензирование → Принять/Отклонить) и отчёт на русском:
   - что исправлено (сводка из `fix_layout.py` и твои правки);
   - что осталось на автора — все пункты с пометкой `автор` с указанием места;
   - по каким стандартам проверено (с их статусом) и по какой методичке, если она была;
   - что спорно или не задано профилем.

## Если прислали PDF

Исправить PDF нельзя, но проверить можно:
```
python3 $NK/scripts/pdf_audit.py work.pdf --profile <id>
```
Скажи пользователю, что это проверка по свёрстанным страницам (поля и интервал — приблизительно), и попроси .docx, если нужны исправления. Срабатывание «ссылка на рисунок без подписи» в PDF перепроверь глазами: подпись может быть частью картинки.

## Справочники

- `references/gost-7.32-2017.md` — отчёт о НИР и основа учебных работ.
- `references/gost-r-7.0.11-2011.md` — диссертация и автореферат; там же про Постановление № 842.
- `references/bibliography.md` — описание источников по ГОСТ Р 7.0.100-2018.
- `references/gost-r-7.0.5-2008.md` — ссылки в тексте.
- `references/eskd.md` — ГОСТ Р 2.105-2019 (ЕСКД).
- `references/calibration-2026-10.md` — как оформляют защищённые работы на практике и почему часть правил — предупреждения, а не ошибки.

## Чего не делать

- Не менять титульный лист: у каждого вуза свой шаблон, только отметь явные проблемы.
- Не переписывать текст, не «улучшать» формулировки, не исправлять орфографию без просьбы.
- Не придумывать номера рисунков, таблиц и источников, которых нет.
- Не принимать правки за автора: файл сдаётся с видимыми исправлениями.
