# Нормоконтроль документа

Главное правило: меняем только оформление. Формулировки, выводы, цифры и цитаты автора не трогаем. Ошибки содержания (ссылка на несуществующий рисунок, нет источника) — в отчёт, а не молча в текст.

## Где лежат инструменты

`NK` — каталог, где рядом лежат `scripts/`, `profiles/` и `references/`:
- в репозитории — его корень (скилл лежит в `.claude/skills/normokontrol/`, значит `NK=../../..` от него);
- в собранном скилле (`scripts/build_skill.sh`) — сам каталог скилла.

Зависимости: `pip install python-docx PyYAML`. Для рендера нужен LibreOffice (`soffice`) и `pdftoppm`.

Рабочие файлы складывай в отдельный каталог (например, `out/`), исходный файл не перезаписывай.

## Порядок работы

1. **Профиль.** Спроси, по чему проверять: ГОСТ 7.32-2017 (по умолчанию) или методичка вуза. Список — `ls $NK/profiles`. Если методички нет в профилях, а пользователь её прислал — составь профиль-наследник (`extends: gost-7.32-2017`, только отличия, см. `profiles/README.md`), значения бери из методички, а не по памяти. Чего нет ни в методичке, ни в профиле — не выдумывай, спроси или отметь в отчёте.

2. **Проверка до правок.**
   ```
   python3 $NK/scripts/audit.py work.docx --profile <id> --json out/before.json --out out/before.md
   ```
   Покажи пользователю сводку: сколько нарушений, главные группы. Каждое помечено, кто исправляет: `авто` — скрипт, `Claude` — ты, `автор` — только автор.

3. **Механика скриптом.**
   ```
   python3 $NK/scripts/fix_layout.py work.docx -o out/work_nk.docx --profile <id>
   ```
   Исправляет поля, формат, шрифт, кегль, цвет, интервал, отступы, выравнивание, заголовки (прописные, полужирный, по центру, с новой страницы, без точки), подписи («Рис. 1.» → «Рисунок 1 —»), номера страниц. Всё — в режиме рецензирования. Строки «Не удалось исправить автоматически» из вывода переходят в шаг 4.

4. **Смысловое оформление — сам.** Повторно запусти `audit.py` на `out/work_nk.docx` и разбери пункты с пометкой `Claude`:
   - заголовок без стиля «Заголовок» — назначь стиль Heading нужного уровня;
   - подпись не на своём месте (у таблицы — над, у рисунка — под) — перенеси абзац;
   - заголовок списка источников — приведи к профилю;
   - список источников — сверь каждую запись с `references/bibliography.md`, исправь знаки и порядок элементов; недостающие сведения (год, страницы, дата обращения) не выдумывай — в отчёт;
   - порядок источников, если профиль требует `by_citation`, — предложи автору, сам не переставляй без согласия: это меняет номера ссылок в тексте;
   - содержание, набранное вручную, — посоветуй собрать автоматически.

   Правь XML через python-docx/lxml и вноси изменения как рецензирование: для текста `w:del`/`w:ins`, для свойств `w:pPrChange`/`w:rPrChange`. Готовые помощники — класс `Revisions` в `scripts/nk_tracked.py` (`replace_span`, `para`, `run`). Если доступен скилл `docx`, можно опираться и на него.

5. **Рендер и проверка глазами.**
   ```
   ACCEPT=1 $NK/scripts/render_check.sh out/work_nk.docx out
   ```
   Посмотри PNG страниц: титульный лист без номера, структурные элементы с новой страницы, рисунки по центру, подписи на местах, ничего не съехало. Нашёл проблему — исправь и отрендери снова.

6. **Сдача.** Отдай `out/work_nk.docx` (правки видны в Word: Рецензирование → Принять/Отклонить) и отчёт на русском:
   - что исправлено (сводка из `fix_layout.py` и твои правки);
   - что осталось на автора — все пункты с пометкой `автор` с указанием места;
   - что спорно или не задано профилем.

## Чего не делать

- Не менять титульный лист: у каждого вуза свой шаблон, только отметь явные проблемы.
- Не переписывать текст, не «улучшать» формулировки, не исправлять орфографию без просьбы.
- Не придумывать номера рисунков, таблиц и источников, которых нет.
- Не принимать правки за автора: файл сдаётся с видимыми исправлениями.
