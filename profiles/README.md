# Профили оформления

Профиль — набор значений для проверки и исправления документа одного типа по одному стандарту. Какой профиль для какого документа — в `catalog.yaml` (там же статус стандартов).

| Профиль | Документ | Стандарт |
|---|---|---|
| `gost-7.32-2017.yaml` | отчёт о НИР | ГОСТ 7.32-2017 |
| `student-work-gost-7.32-2017.yaml` | ВКР, курсовая, реферат, отчёт о практике | ГОСТ 7.32-2017 без требований, специфичных для НИР |
| `gost-r-7.0.11-2011-dissertation.yaml` | диссертация (рукопись) | ГОСТ Р 7.0.11-2011 |
| `gost-r-7.0.11-2011-autoreferat.yaml` | автореферат | ГОСТ Р 7.0.11-2011 (только структура) |

Метаданные профиля: `document_types` — типы из каталога, `standards` — id стандартов из каталога, `readiness` — `ready`, `beta`, `limited`.

## Правила

- Значения берутся из текста стандарта; рядом в комментарии — номер пункта.
- То, чего стандарт не задаёт, в профиль не пишем. Если правило — общепринятая практика, а не требование стандарта, так и помечаем в комментарии.
- `null` означает «правило не задано»: так наследник отменяет требование базового профиля.
- Отступ можно задать числом (`1.25`) или диапазоном (`[1.25, 1.7]`); при исправлении ставится первое значение.

## Профиль вуза или диссертационного совета

Методичка почти всегда отличается от ГОСТа в мелочах: кегль, поля, титульный лист. Профиль наследует профиль из каталога и переопределяет только отличия:

```yaml
name: Методичка <вуз>, <год>
id: <vuz>-<тип>-<год>
extends: student-work-gost-7.32-2017

text:
  size_pt_min: 14
```

Для требований совета — `extends: gost-r-7.0.11-2011-dissertation`. Поле `document_types` в профиле вуза не указывайте: `catalog.py` сам покажет его под нужным типом документа.

Название файла совпадает с `id`: `<вуз>-<факультет или тип работы>-<год>.yaml`. В pull request приложите ссылку на методичку.
